How it works

Three steps. No account, no trace left behind in this browser after the burn.

01

Write & encrypt

You type a secret. Your browser generates a random 256-bit AES-GCM key and encrypts the text on your device — before anything is stored. The plaintext never leaves your browser.

02

Share the link

You get a link like secretdrop…#s=abc123&k=…. The key is in the # fragment of the URL. Fragments are never sent to a server, never stored in this demo, and never appear in server logs.

03

It burns

When the recipient opens the link, the browser decrypts the secret with the key from the fragment — then deletes the encrypted copy. Open it again and all you get is “burned / expired”. Time-based secrets expire on their timer instead.

🔥 Burn rules, plainly

  • After 1 view: the first successful open deletes the secret. A second open shows “burned”.
  • 1 hour / 24 hours / 7 days: the secret can be opened until the timer ends, then it is deleted and shows “expired”.
  • Wrong password or wrong key: nothing is shown, nothing is deleted — the view does not count as a read.
  • Burn now: the creator can delete a secret at any time from “My secrets” below.

💡 Share it safely

  • Send the link in one channel and the password (if any) in another.
  • Tell the recipient to open it only when they are ready to copy it — one view means one chance.
  • Do not post a one-time link in a public chat. Anyone with the link and password can open it first.
  • For truly sensitive material, use the production, server-backed version — not this local demo.

Security model — honest version

What is protected, what is not, and what this demo cannot do.

✓ What this does

  • AES-256-GCM encryption via the browser WebCrypto API, with a fresh random key and IV for every secret.
  • Optional password protection: the key is wrapped with a PBKDF2-derived key (250,000 iterations, SHA-256, random salt), so the link alone cannot open it.
  • The key is only in the URL fragment (#k=…). Fragments are not sent in HTTP requests.
  • Burn-after-reading and expiry are enforced on read; burned secrets are removed from storage.

⚠ Honest limitations

  • Local-only demo: secrets live in localStorage in this browser. A link only works on the same browser / device that created it. There is no server, so there is no server-side deletion.
  • Anyone with this browser can open DevTools and read the encrypted data in localStorage — they still cannot read the plaintext without the key / password.
  • Do not use this demo for real credentials, banking details, or anything whose leak would cause real harm. Use a proper server-backed secret service for that.
  • Clearing browser data, private mode, or a different browser will make links unreadable — that is expected for a local demo.
